# 網頁搶答與麻將解答加速（2026-10-22）

## 牌面說明

「面子」是一組順子（同花色連續三張）或刻子（三張相同）。原「已固定完成的4組面子」表示其他12張已湊好，本題只看上方尚待完成的4張手牌。已改成「已湊好的4組順子／刻子（這題只看上面的手牌）」。第五題有三組固定面子，剩七張待完成，規則及經驗算的正解不變。

## 解答反應

原本主持人動作儲存後，會等待完整 /api/state 刷新才能更新畫面，若既有讀取尚未完成還需排隊。麻將動作現在直接回傳已儲存的 mahjong 和 projection，手機確認成功即渲染，不再等待完整資料讀取。背景讀取使用修訂號與忙碌狀態保護，舊回應不會把新解答蓋回題目。投影沿用約每秒同步，仍受實際網路影響。

## 搶答操作

1. 賓客掃既有 QR、完成姓名與頭像報到，點上方「⚡ 現場搶答」，保持在前景。
2. 主持人於「小貓迷因」操作區，或後台「摸麻將」頂端的現場搶答控制，輸入本輪名稱並按「①準備新一輪」。
3. 先出題、確認大家都進搶答頁，按「②開始5秒倒數」。倒數由伺服器計時，早按即使自行發送請求也不會被接受。
4. 開放後第一筆成功寫入資料庫的搶答為得主，本輪立刻關閉。賓客、手機主持人與電腦投影都顯示得主姓名，邀請其上台回答。
5. 可「關閉／收起投影提示」關閉未完成搶答或收起得主橫幅，得主記錄保留到準備下一輪。再次準備將換新輪次；在進行中的一輪重設會確認。

每輪一位、不在網頁輸入答案或自動判對錯、不自動換輪。網路速度與延遲會影響搶答順序，因此採「伺服器成功受理」而不是宣稱所有裝置絕對同時；不能保證等同現場實體搶答器。沒有手機者可由事先指定的人代按同一位賓客的報到身分。

## 實作與驗證

既有 settings 存 buzzer，無新表、無資料清除、無遷移。輕量 GET /api/buzzer 只讀一次設定，公開資料只含輪次、狀態、標題、開放時間、得主姓名與時間，不公開 guestId、憑證。POST 走既有管理及賓客驗證，SQL 條件更新保證每輪至多一位，鎖定已報到身分姓名，忽略自行傳入姓名／時間。輪次 ID 防舊請求竄到新輪；同得主重試回傳相同結果。主持人開／關及準備亦檢查輪次，避免舊主持人頁誤動新輪。

可見搶答頁、可見主持控制及電腦投影每秒讀輕量狀態；一般賓客離開搶答頁／網頁背景時停止搶答輪詢。畫面倒數以伺服器時間校準，網路錯誤不冒稱成功；過時輪詢無法蓋過已確認的得主。

128項自動測試通過，含150位不同報到身分並發的單一得主、重試、舊輪次、搶跑、權限、偽造身分欄位、隱私、主持人收起橫幅、本機倒數及失敗狀態、麻將即時解答與舊讀取覆蓋保護。150人是本地資料庫邏輯測試，非Cloudflare正式站實測壓力。TypeScript與建置通過，未用實體手機瀏覽器測試。
