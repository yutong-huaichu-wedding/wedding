# 宇童 ♡ 懷筑｜婚禮網站

這個網站已取代原本 GitHub Pages 的單一 `index.html` 網站。原版保留在 Git 提交 `aa6d00a`。新網站包含賓客報到、頭像、婚禮相簿、祝福彈幕、快問快答、大樂透與主持人控制台。

## 架構

- GitHub：保存程式碼。
- Cloudflare Workers：執行網站與 API。
- Cloudflare D1：保存賓客、留言、題目、答題與彩券。
- Cloudflare R2：保存賓客上傳的照片與頭像。

GitHub Pages 無法單獨執行本專案的 API。根目錄的 `index.html` 會把原網址 `https://yutong-huaichu-wedding.github.io/wedding/` 轉到 Cloudflare Workers。婚禮 QR Code 指向 GitHub Pages 原網址，以便將來更換 Workers 網址時不用重印。

對外分享的免費短入口為 `https://yutong-huaichu-wedding1212.pages.dev/`，其原始碼在 `short-url/index.html`。這是 Cloudflare Pages 的靜態轉址頁，訪客進站後瀏覽器會顯示較長的 Workers 網址；所有互動與資料仍由原本的 Worker、D1 與 R2 處理。已產生的 QR Code 仍指向 GitHub Pages 原網址，繼續可用。若日後更改 Worker 網址，需同步修改 `short-url/index.html` 與根目錄 `index.html`。

## 首次部署（Cloudflare 帳號持有人執行）

1. 使用 Node.js 22.13 以上，執行 `npm ci`。
2. 執行 `npx wrangler login`，登入你的 Cloudflare 帳號。
3. 建立 D1：`npx wrangler d1 create yutong-huaichu-wedding`。把回傳的 `database_id` 填入 `wrangler.jsonc`，取代全 0 的測試 ID。
4. 建立 R2：`npx wrangler r2 bucket create yutong-huaichu-wedding-photos`。
5. 依序執行：
   - `npx wrangler d1 execute DB --remote --config wrangler.jsonc --file drizzle/0000_cold_namorita.sql`
   - `npx wrangler d1 execute DB --remote --config wrangler.jsonc --file drizzle/0001_yielding_magus.sql`
6. 執行 `npm run build`，接著執行 `npx wrangler deploy --config dist/server/wrangler.json`。
7. 執行 `npx wrangler secret put ADMIN_PASSWORD --name yutong-huaichu-wedding`，在提示時設定主持人密碼。密碼不要提交到 GitHub。

部署後先用兩台手機測試姓名與頭像報到、照片上傳、留言、遊戲與主持人登入，再安排 100 位以上的壓力測試。

相簿會在瀏覽器壓縮照片，單張最多 600 KB、每位賓客最多 4 張；頭像最多 120 KB。伺服器以 D1 的 `media` 表記錄已使用容量，達 1 GB 後拒絕新上傳。R2 bucket 使用 Standard 儲存類別。一般頁面每 60 秒更新一次，快問快答每 3 秒、大樂透每 8 秒、祝福牆每 10 秒、主持人畫面每 3 秒，背景分頁每 120 秒更新一次。這些限制控制儲存量、寫入次數與一般瀏覽的請求量，但不能保證讀取次數永遠不超過免費額度。Cloudflare 的帳單提醒是通知，不是自動停用服務的硬上限。

## 現場畫面與操作

| 功能 | 賓客手機 | 主持人控制台 | 現場投影 |
| --- | --- | --- | --- |

| 祝福牆 | 送出祝福、瀏覽留言與緩慢飄過的彈幕。 | 查看或刪除留言，開啟祝福牆投影。 | 祝福與姓名、頭像以彈幕飄過。 |

主持人在控制台按「試玩模式」，可在自己的分頁操作快問快答與大樂透，右側同步顯示賓客手機畫面的模擬版。試玩不寫入 D1，也不會出現在正式賓客或投影畫面；關閉試玩後模擬資料清空。投影畫面須由主持人電腦連接現場螢幕，再從控制台開啟。

## 參賽與主持人新操作

- 賓客報到後到「互動遊戲 → 快問快答」按「我要參賽」。報到本身不會加入參賽。
- 每題出題時固定名單；中途加入，從下一題起作答。關閉網頁或斷線不算退出。
- 按「退出參賽」時，未答本題者從本題人數移除；已答者保留本題答案、分數及人數，下一題不再加入。
- 本題所有參賽者答完，立即截止並公布答案；沒有參賽者時不自動公布。主持人仍可手動截止，截止後才能開下一題。
- 賓客、主持人及投影可看到本題已回答／參賽人數。已加入的總人數另外顯示，可能包含等待下一題的人。
- 「重新開始測驗」仍會要求確認並清除問答答案、分數；保留已選擇參賽的名單。更新網站本身不會執行這個操作。
- 主持人登入後，在「婚禮相簿」每張照片下可直接按「刪除照片」，先查看大圖再確認刪除。「留言與相片」也提供相同操作。
- 「樂透控制 → 幸福投注站」可直接選已報到賓客、點選六個不同號碼並確認代投。同名賓客以報到順序區分，已投注者標示且不可重複投注。後台與賓客選號互不影響。
- 試玩模式模擬一名已加入的參賽者，答完即自動公布答案；仍不呼叫正式遊戲 API。

本次使用現有 settings 表保存參賽設定，不需新增資料表、執行資料庫遷移、重設資料或更換分享入口及 QR Code。若更新時舊版已經開題，先手動截止該題，再開下一題；舊題不會自動替賓客加入參賽。

## 小貓迷因問答（現場舉手版）

主持人控制台新增「🐱 小貓迷因問答」入口，開啟 `/cat-memes.html`。

1. 在主持人電腦新增題目，填名稱與解答，上傳照片和一支自帶聲音的 MP4／WebM 答案影片，再按儲存。內建 13 題中有 12 題備妥有聲影片；質問貓仍待補；Huh 貓採用使用者提供的照片。
2. 按「出題」或上一題／下一題，投影只顯示照片，賓客舉手模仿聲音。
3. 按「公布解答＋播放有聲影片」，才顯示解答並播放影片；畫面與聲音來自同一檔案，可重播或重新藏起答案。
4. 「開啟獨立投影」會開另一個視窗。將它移到同一台電腦的延伸螢幕，先按「啟用投影音效」，並在開場前用喇叭實測。若瀏覽器未自動播放，按答案下方「再播一次」。主持人耳機試音只在主持人這台電腦播放。
5. 題庫只保存在目前電腦及瀏覽器，不同步至 D1 或其他裝置；請用「匯出題庫備份」保存含照片與影片的 JSON。到現場換電腦時，匯入同一份備份即可。主持人頁面需保持開啟，獨立投影供同機延伸螢幕使用。

最多 40 題，單張照片 8MB、單支有聲影片 12MB，整份素材合計 40MB。題目照片可用 JPG、PNG、WebP、GIF；答案請用有聲 MP4 或 WebM。舊備份中的分開動圖與音檔會保留，但須換成有聲影片才可出題。小貓題庫不讀寫正式賓客、相簿、留言、彩券或快問快答紀錄。

## 題庫編輯反應改善

儲存現有快問快答題目不再等待整站資料重新讀取。移動順序先立即呈現，再依序保存最後的操作；期間保留已展開題目、未儲存草稿及游標位置。儲存中、完成或失敗有各自提示；開始編輯前已發出的舊查詢不會蓋掉新的題目內容。資料無變化時跳過重畫整站畫面。

## 內建 13 題貓貓迷因

順序：Huh 貓、Happy Happy Happy 貓、哭哭香蕉貓、Chipi Chipi 動畫貓、OIIA 旋轉貓、Popcat、No No No 拒絕貓、Nyan 彩虹吐司貓、點頭貓（指定 Ievan Polkka 版本）、Maxwell 黑白旋轉貓。

原題庫第 9、10 題為加分哼歌題，主持人可接受相近旋律，不必要求精確歌名或外語發音。點頭貓與旋轉貓有多種配樂，此題庫指定的版本與判定提示已寫在各題中。音效以短片段呈現，避免長音樂拖慢現場節奏。

第一次開啟時載入內建題庫；已儲存的舊內建動圖與音檔會辨識後換成有聲影片，不覆蓋自訂素材或答案。按「加入 13 題迷因題庫」可補入缺少的題目；重按不會重複增加同名題目。

素材來源及選用的短音效見 `public/cat-meme-assets/SOURCES.md`。所有播放仍請在現場的電腦、瀏覽器與喇叭上事先試播。

新增第 11–13 題：希特勒貓（德語貓／湯圓）、質問貓、委屈貓。質問與委屈分成兩題，按先質問、再委屈回應的順序，主持人可邀請兩位賓客接力。德語貓只要求模仿語氣，不要求德文或台詞。

德語貓與委屈貓已有有聲影片。質問貓的原音來源目前無法取得，明確標示待補，未使用其他貓叫冒充。準備該題時請上傳相符的有聲影片，再按儲存。

## 小貓題庫排序

每張題目卡新增「↑ 上移／↓ 下移」。位置立即更新並自動儲存，連續移動會依序保存最後順序；儲存失敗則還原最近成功儲存的順序並提示。排序保留正在投影的同一隻貓、答案顯示狀態及編輯中的欄位，不重播音效。匯出／匯入備份與再次補入內建題庫都會保留自訂順序。

完整上線說明見 `docs/PUBLISHING.md`：可沿用原本有登入 Cloudflare 的電腦更新原 Worker，或在 Cloudflare 將原 Worker 連接既有 GitHub 儲存庫。此工作副本尚未部署。
